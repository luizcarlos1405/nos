# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"NOS Dourados" (NOS = Núcleo de Organização Social, provisional name) is a static, no-build site (plain HTML/CSS/vanilla ES modules, no package.json, no tests, no linter) of three pages:

- **Início** (`index.html`, `js/home.js`): the greeting of this hour on the sky, the next activity resting on the band (its date circled by hand, a link to send it to WhatsApp; from 760px also "Compartilhar no WhatsApp", "Ver na agenda" and "Também na agenda", the next three), and a door to each page: the agenda and Comércio.
- **Agenda** (`agenda.html`, `js/app.js`; `calendario.html` until 2026-10-27, now a page that forwards to it): one permanent calendar of the activities of the social movements, unions, student groups, Indigenous and quilombola organizations, councils and parties of Dourados/MS, as a list of days or a month. For each activity it generates a WhatsApp-ready message and a 1080×1350 PNG flyer. Called "Agenda" in the UI since the Céu · Terra redesign (2026-10-27); the address stays `calendario.html`. Until 2026-10-26 it was `index.html`.
- **Comércio** (`comercio.html`, `js/comercio.js`): the businesses that answered the network's registration form (a Google Form), A to Z, each with what it offers, its WhatsApp numbers (with a phone glyph to call), Instagram and links, search, category chips and an "Indicar no WhatsApp" message. It was paused ("Em breve") from 2026-10-27 to 2026-10-28; the home's door shows how many businesses there are.

Language rule: development (code, identifiers, CSS classes, comments, commit messages) in English; all content and UI strings in Brazilian Portuguese (pt-BR). Content-like slugs (flyer PNG filenames: `folha`, `mes`, `cartaz`, `cancelada`; the query values `?tema=escuro`, `?ceu=noite`) stay in pt-BR.

Product truth lives in `PRODUCT.md`; the visual direction ("Céu · Terra": the sky of Dourados at this hour over a woven band, the land below) and the direction contracts live in `.impeccable/surfaces/` (`index-html.md` for the home, `agenda-html.md` for the agenda, `comercio-html.md` for Comércio); `DESIGN.md` (+ `.impeccable/design.json`) documents the built design system. The design source is `design/`: one HTML file per artboard (the approved Céu · Terra artboards, the other directions of the round, the band's research, the mark, the four flyers), all shown on one zoomable canvas by `design/index.html` (see "Designs"). Use the project's impeccable skill for UI work.

## Running

The pages must be served over HTTP: ES modules and the `fetch` of the CSVs fail under `file://` (an inline script in `agenda.html` and `comercio.html` shows an error notice in that case).

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

Deploy = publish the whole folder to any static host. It is live on GitHub Pages at https://nos.dourados.social (`CNAME`); `SITE_URL` in `js/config.js` and the link-preview `canonical`/`og:url`/`og:image` tags of the three pages hold that address.

## Pages and navigation

- Three HTML files linked with plain `<a href="agenda.html">` links, so any static host serves them (no router, no rewrites; GitHub Pages also answers `/agenda` without the extension, but links and messages always use the file name). `index.html` is the root. `calendario.html` is the agenda's old address (until 2026-10-27): a stub that forwards to `agenda.html` keeping the query and the hash, so links already shared in WhatsApp groups and old shortcuts keep working; keep it, and its line in `sw.js`'s SHELL.
- Every page opens with the same header on the sky (`header.site-head`): the sun or the moon and the stars (`.sky-art`, `aria-hidden`), then a grid (`.site-head-inner`) with the brand (`a.brand`: the NOS mark and "Dourados", "(página inicial)" for screen readers), the pages' links (`nav.site-nav`, one `a.nav-link` per page, the open one with `aria-current="page"`), the theme button (`button.theme-toggle`, `data-theme-toggle`), and the page's name (`.page-title`: `h1.page-name` and the line `#page-sub`, "4 atividades até 20/11" on the agenda) or, on the home, the greeting (`.hello`). Phones (under 760px): the page's name beside the theme button, no brand (the home shows it), and `nav.site-nav` becomes a bar fixed along the foot of the screen (the body pads for it); from 760px the brand, the links and the button share a 68px bar and the name or greeting sits under it. One `nav` serves both places. Under the header, the band (`div.band`, the horizon); at the foot of every page `footer.site-foot` with the full name and the band's provisional credit. The home's brand carries `aria-current="page"` too.
- `index.html`'s head holds the notes on the shared tags (browser colour, theme and sky, icons, manifest, home-screen app, link preview); `agenda.html` and `comercio.html` repeat the tags with a pointer there, changing only the title, descriptions and addresses. The three heads carry the same inline script (theme and sky before the first paint) and the same two `theme-color` metas.
- `js/page.js` is what the pages share: `$`, `el`, `escapeHtml`, `safeUrl`, `initPage(name)` (the brand from `js/config.js`, the footer's full name, the tab title "Comércio · NOS Dourados", the icons of `[data-icon]` nodes, and `initSky()`), `showNotice`/`showOffline(savedAt, what)`/`announce` (`#notice`, `#live`), `readSheet(url)` (fetch with the cache fallback, `decodeCSV`, `parseCSV`, plus `savedAt` from the worker's `X-Cached-At`), and `registerWorker()`. `js/sky.js`: `skyPeriod(date)`, `greeting(date)` and `initSky()` (see "Light, dark and the sky").

## Data

The agenda is a Brazilian CSV (`;`, UTF-8 BOM, dd/mm/aaaa) read from `CSV_URL` in `js/config.js` (now `data/agenda.csv`; later a published Google Sheets CSV). Columns (pt-BR headers, matched loosely by `COLUMN_ALIASES` in `js/events.js`: accents/case/spaces normalized, English aliases accepted): `Título`, `Dia` (required; a full date with the year — yearless dates are rejected so they can't change meaning at New Year); `Dia final` (multi-day; a yearless value takes the start's year, or the next one if it would fall before the start), `Horário`, `Término` (both accept `9h`, `9h30`, `09:30` and spreadsheet time cells like `14:00:00`/`2:00 PM`; an end time alone renders "até 12h"; no time at all renders "Horário a confirmar", never "dia todo"), `Tipo`, `Organização` (split on `,`/`;` outside parentheses, main first → `event.orgs`), `Setor` (alias `Categoria`), `Local`, `Cidade` (empty, `HOME_CITY` or `HOME_CITY` + state = here → `event.city` is `''`), `Descrição`, `Contato`, `Link` (action link), `Fonte` (source post), `Visível` (unchecked = draft, skipped silently, `isHidden`), `Cancelado` + `Motivo Cancelamento` (`isChecked`), and `Notas internas` (ignored by the site). `parseCSV` (`js/csv.js`; the Windows-1252 fallback is in `decodeCSV`) returns each record's spreadsheet row (`lines`) so notices name the right "Linha N" even after blank rows. `buildEvents` returns `{ events, invalid, warnings, missing }`: rows without a title or a full date are reported (folded list in the notice), an unreadable `Dia final` keeps the row as one-day with a warning, and missing `Título`/`Dia` headers produce one error naming them. `data/agenda.csv` was extracted (and adversarially verified) from an Instagram survey of the organizations (`../coleta-instagram/*.md`, next to the project folder and kept outside this repository) and the raw captions; its `Notas internas` say what is uncertain and why rows are hidden. `agendaSummary(events, now)` (the agenda's top line and door: "4 atividades até 20/11", cancelled ones left out) and `orgFullName(org)` (`ORG_NAMES`) live in `js/events.js`.

Comércio reads `COMMERCE_CSV_URL` (now `data/comercio.csv`; later the form's answer sheet published as CSV), same formats. The columns are the Google Form's questions as they are, matched by a word they contain (`COLUMNS` in `js/businesses.js`, checked in order: consent before contact before other networks, so "Como podemos entrar em contato?" and "Podemos incluir … com a rede?" land right): `Carimbo de data/hora` (ignored), `Nome da empresa ou negócio` (required), `Cidade e estado`, `Qual o Instagram da empresa?`, `O que sua empresa oferece?`, `Como podemos entrar em contato?`, `Sua empresa tem site ou outra rede social?`, `Podemos incluir sua empresa na nossa planilha e compartilhar suas informações com a rede?` (only a yes is shown, `isChecked`; a sheet without the column shows every row), plus columns the NOS team adds to the right: `Categoria` (free text; the order of the chips is `COMMERCE_CATEGORIES`, then alphabetical), `Visível` (`isHidden`) and `Notas internas` (ignored). `buildBusinesses` returns `{ businesses, invalid, missing }` sorted by name (pt-BR collation); rows without a name are reported, rows without consent or hidden are skipped silently. What it reads out of the free text, and nothing else: the name and a subtitle (" - " or a trailing "(…)"), the letter (`#` for digits and signs), an all-caps offer in sentence case, the city (`HOME_CITY` with or without the state → `''`; others title-cased, another state as "City/UF"), Brazilian phone numbers with their area code in the contact answer (11 digits with a 9 → mobile: WhatsApp link and a call glyph; 10 → landline; numbers without the area code stay text), the Instagram handle (a link, "@handle" or a bare handle, accents stripped, a bare "Sim"/"Instagram" refused), the links of the other-networks answer named by domain (Google, Facebook, TikTok, Instagram, WhatsApp, else "Site"), and the answers' own words as notes when they add something (`contactNote` when no number was found, `otherNote` unless it only names channels already shown or says no). Ids are `biz-<slug of the name>`; `search` is the accent-free text every typed word must appear in. `data/comercio.csv` holds the answers of 2026-10-26 verbatim, with a `Categoria` filled by hand.

## Architecture

Agenda data flow: `app.js` fetches CSV → `csv.js` `parseCSV` → `events.js` `buildEvents` → views (`agenda.js`, `month.js`) → clicking an activity fills the panel ("bench") from `app.js`, with `whatsapp.js` (message + `wa.me` link + preview) and `flyer.js` (flyer DOM + PNG export). Comércio: `comercio.js` → `page.js` `readSheet` → `businesses.js` `buildBusinesses` → the list. Início: `home.js` reads the agenda's sheet and, for Comércio's door (`renderCommerceDoor()`), the businesses' sheet.

- On the desk (1100px) the agenda's column puts the organization filter beside Lista | Mês and the group chips under both, wrapping from the left edge (`.filters` steps aside with `display: contents`; it has no role of its own). The activity open in the panel takes a quiet soft-ink ring.
- `js/app.js` is the only stateful module of the agenda: one `state` object (view, group filter set and organization filter as `matchKey` values, selected activity, past toggle, month/year, selected day, the month grid's keyboard position) and all DOM wiring. Other modules are render/format helpers that take data and return DOM nodes or strings. Rendering is full re-render via `replaceChildren()`; no framework.
- Focus across re-renders: every rebuildable focusable node carries `data-focus` (`chip:<key>`, `line:<id>` on the activity cards, `day:<key>`, `month:prev|next|today|title`, `past-toggle`, `clear-filters`); `rerender()` puts focus back on the new twin (with fallbacks in `FOCUS_FALLBACK`). Screen-reader announcements go through the persistent `#live` region (`announce()`), never through re-rendered nodes.
- "Now" is not frozen: `today`/`todayKey` are updated by `tick()` (every minute, on `visibilitychange`/`pageshow`); the view and the top line re-render when the day turns or the next activity changes, and the CSV is fetched again after 30+ minutes hidden (`reload()`, keeping filters and selection while they still exist; if the fetch fails, what is on screen stays, without an error). The home does the same for its greeting (the hour), its date and its card (`tick()`, `load()` in `js/home.js`); `js/sky.js` keeps the sky's hour on every page.
- Event object shape is defined in `buildEvents`. Ids are stable across re-fetches: `ev-<dateKey>-<slug of the title>` (`-2`, `-3`… for repeats), so rows inserted above don't swap the open activity for another. Dates are local `Date` objects, never UTC; `dateKey` (`YYYY-MM-DD`) is compared as a string. Multi-day activities have `endDate`/`endDateKey`; helpers `lastDayKey`, `dayKeys`. Times are minutes since midnight (`time`, `endTime`) next to the raw strings; formatters fall back to the raw text. `matchKey` (punctuation-free) matches people-typed names (sectors, organizations, cities).
- List (`agenda.js`): the days on the land (`section.day-group`, its `h3.day-head` "Hoje · terça, 27/10" with Hoje underlined by hand, "Sábado, 31/10", a holiday's name and a "Feriado" tag; the full date for screen readers), each with its activities as cards (`button.event-card`, `renderCard`: the title and a share mark, then the time, the organization with its group's dot and its full name where known (else its group), the place, and a multi-day period). Today is always listed ("Nada marcado para hoje" when empty); holidays between the first and the last listed day are listed as day lines. Past days are hidden until "Ver N atividades anteriores"; a multi-day activity that started before today is listed under today ("Em andamento, até …", `groupByShownDay`); each day lists its own activities by time, then the running ones (`dayOrder`). With filters on and nothing ahead, a quiet block with "Ver atividades anteriores" / "Limpar filtros". The type stays in the panel and the message, not on the cards.
- Month (`month.js`): Sunday-first, built as week rows inside a card; Sundays and holidays are shaded as days off (`is-off`), today's numeral is underlined by hand, the next activity's day circled, the chosen day ringed in soft ink (a quiet mark: the strong ring is focus's). On phones one-day activities are their groups' dots and multi-day ones thin bars in lanes along the foot of the week (`weekBars`, each day reserving only the lanes that cross it); from 1280px each day lists its entries (dot, time, title, three lines at most) and the bars are tinted with the group's colour, its dot and the title in ink. The grid is one tab stop with arrow/Home/End/PageUp/PageDown navigation (`onMove`). The chosen day is listed under the month (`renderDay`, only while that day is on the month's page); from 1280px a holiday's name sits on its own line under the numeral and its week (`has-holiday`) makes room for two lines, so the bars stay level; turning the month picks today or the month's first day with activities; picking a grey day flips to its month.
- Days off: Sundays and national holidays (`holidays.js`: fixed dates + Good Friday from Easter; `EXTRA_HOLIDAYS` in config for local ones — none confirmed yet). `isRedLetter` names them in code (the month flyer prints them in the sky's soft ink).
- The next activity (`findNext` in `app.js`, computed on the filtered list, through `findNextEvent`/`upcomingEvents` in `events.js`, which the home shares): first non-cancelled activity starting today-or-later (today's count until an hour after they start; periods already running are not "next"). Its time is circled by hand in urucum with "a próxima" on its start day's card (`handMark` in `js/icons.js`), its day circled in the month, and its panel says "a próxima"; on the home its date is circled.
- Panel ("bench"): bottom sheet under 1100px, persistent sticky column at ≥ 1100px (`desktop` in `app.js` and the 1100px media queries in `style.css` must agree). The phone sheet is a modal dialog (`setModal`: `role=dialog`, `aria-modal`, `inert` on the header, `#main` and the footer), adds a history entry so the phone's Back button closes it (`openSheet`/`closeSheet`/`hideSheet` + `popstate`), and can be dragged down by its head (`wireSheetDrag`, `--drag`). Head: the day in Bricolage ("Sábado, 31 de outubro"; a period as "Sex, 09/10 a Dom, 11/10"), the time or "Horário a confirmar", "a próxima"; struck through when cancelled. Facts list (organization with its dot and full names from `ORG_NAMES`, period, place, type, contact, link, source), description, Mensagem/Panfleto tabs (`showPanel`; flyer mode folds facts and description via `data-panel`, keeping only the organization row on desktop; on screens under 700px tall, switching to Panfleto scrolls the format bar to the top), sticky action bar. Phone numbers in `Contato` become links (`contactNode`: mobiles → `wa.me`, landlines → `tel:`); `Link`/`Fonte` go through `safeUrl` (only http(s); bare domains get `https://`; anything else is shown as text). Cancelled: a "Cancelada" tag in ink, the reason, the title struck.
- Flyers (`flyer.js` + `css/flyers.css`): `FLYER_STYLES` (`day` "Folha do dia", `month` "Agenda do mês", `poster` "Cartaz") and `NOTICE_STYLE` (`notice` "Aviso de cancelamento", forced for cancelled activities). Class prefixes `dy-`, `mo-`, `po-`, `nt-` under `.fl--<id>`, shared parts `fl-*`. `renderFlyer` builds a fixed 1080×1350 node (`aria-hidden`, `data-sky`); the panel preview scales it with `transform: scale()` on `#flyer-scaler`. Each flyer is a landscape of the site's world: the sky of the hour the activity starts (`skyOf`, js/sky.js's hours; no time → the day's sky) in five flat bands, the woven band (64px) as the horizon, and the land: the light theme's clay under the dawn, day and dusk skies, the dark theme's terra roxa under the night (`css/theme.css` gives `.fl` its own sky and land roles by `data-sky`, whatever the page's theme and hour). The sky carries the flyer's idea in Bricolage, the land the activity in Inter (the title; the organizations as runs, each name in 700 with its full name from `ORG_NAMES` in soft 500, "e mais N" when they are many; the place with its city outside Dourados) and NOS's signature (the mark, "Dourados", "Agenda das organizações", `SITE_URL`'s address). Folha do dia: the day's numeral stands on the horizon in front of the rising sun (under the small moon and the stars at night), the weekday and the month from its top line and the time (its end apart: "19h30", "às 22h30") or "Horário a confirmar" on its baseline; a holiday is named on the land under the title. Agenda do mês: the weeks are the sky's bands (band 5 the last week), the activity's day is the sun or the moon in the hand's loop, a period's other days underlined by hand, Sundays and holidays in the soft ink. Cartaz: the title as large as the sky allows, hanging from the top with the sun rising under it by day, standing on the horizon under the moon at night; on the land the date circled by hand with the time. Aviso: "Cancelada" on the sky of its hour without its sun or moon (the stars stay at night) over the date struck by the hand; on the land the title struck by an urucum stroke, the reason, then who and where. The activity's type is left off the flyers, as off the cards. Sizes, line breaks and the sky's positions are planned deterministically (no DOM measurement) from the glyph advance widths embedded in flyer.js and vertical metrics measured with them (Bricolage Grotesque 700/800 with its optical size pinned at 96 by `.fl`'s `font-variation-settings`, Inter 500–700; `.impeccable/flyer-metrics.html` prints the tables: run it again after changing a font, a weight or the optical size), so the preview and the PNG match; flyers.css mirrors the measures flyer.js plans with (line heights, gaps, a row's slot): change them together. The sky's bands are placed around its type (`clearEdges`: no edge across a line of text or within 20px of it, display type from 100px only keeping its cap line, x-height and foot clear; bands at least 40px, a search preferring them near `BAND_TOPS`'s shares and growing up from the horizon); titles shrink before they are cut and take a line more rather than end one on a short word (a line may start one: "e do Conselho Fiscal"), and the poster's title gives up to 14% of its size for lines that read better. Export uses the global `htmlToImage` (vendored in `js/vendor/`) after `document.fonts.ready`. `.impeccable/flyer-lab.html` renders every style for real and stress-test activities with an automatic audit (ink boxes on the sky and the land, collisions, lines inside their boxes, band edges clear of the type, contrast of 4.5:1 or more against the band, the sun or the land under each text; dev only; English). The canvas's flyer artboards draw them with flyer.js too (see "Designs").
- Início (`js/home.js`): the greeting ("Bom dia" until noon, "Boa tarde" until 18h, "Boa noite" after; an inline script after it in `index.html` sets it before the first paint) and the date; the card `#next-card` resting on the band (the date circled, "a próxima, hoje/amanhã", the share link `wa.me/?text=` with the activity's message, time, organization, place; from 760px the time beside the date, the organization's full name, "Compartilhar no WhatsApp" + "Ver na agenda", and "Também na agenda" with the next three and "Ver as N atividades até dd/mm"); the doors (`a.door`): the agenda's line from `agendaSummary` and, on phones, its live line (`#door-agenda-next`, what comes after the next one: "Depois, sáb 31/10, 21h: …"; the desk lists it under "Também na agenda"), its description shown only while there is nothing to list. Without the sheet the card says it couldn't load the agenda and the doors stay.
- Comércio (`js/comercio.js`) keeps one `state` (`query`, `categories` as `matchKey` values). The chips are built once and only flip `aria-pressed`, so focus stays on them; `render()` rebuilds the count line and the list (`section.letter-group` with an `h2.letter` and its count, businesses as `article.biz` cards with an `h3` name, what they offer, their category as a quiet tag after it, and a `dl.biz-contacts`), or a quiet block naming the search and the categories, with "Buscar em todas as categorias" when dropping the categories finds something and "Ver todos os negócios". The search filters as you type and announces the count after a pause; Enter closes the keyboard. `breakable()` lets offers and notes wrap after their slashes. "Indicar" is a `wa.me/?text=` link with `buildBusinessMessage` (`whatsapp.js`, closing with `COMMERCE_CLOSING_LINE`): a share glyph on phones (`aria-label`), written out from 760px.

### Light, dark and the sky

- Colours: every colour is a custom property in `css/theme.css`, in two layers — palette (`--color-*`: the raw colours, named for what they are, light and dark both: clay, terra roxa, urucum, ipê-rosa, the sky's bands at each hour, the groups by day and at night) and roles (`--role-*`: what each colour is for). `style.css` and `flyers.css` use roles only; the only literals are `transparent`, `currentColor`, the band's image (`assets/faixa.svg`) and, inside `@media (forced-colors: active)`, system colours. The palette never changes with the theme; the roles do.
- Light and dark: the roles on `:root` are the light theme; `:root[data-scheme='dark']` swaps them (terra roxa ground, moonlit ink, the night's urucum, the groups' lighter colours). The inline script in each page's head sets `data-scheme` before the first paint: the visitor's choice (the theme button: `localStorage` `nos.tema` = `claro`/`escuro`; choosing what the system says forgets it), else `prefers-color-scheme`. `?tema=claro` or `?tema=escuro` forces one for the visit (screenshots, links; not saved). The old named themes (`data-theme`, `?tema=<name>`, the `exemplo` theme) are gone: a variant now means a light and a dark set and the sky's hours, so it is a new pair of role blocks in `theme.css`.
- The sky by the hour: `data-sky` on `<html>` (`dawn` amanhecer 5–9h, `day` dia 9–16h, `dusk` entardecer 16–19h, `night` noite 19–5h, by the local clock; `?ceu=amanhecer|dia|entardecer|noite` forces one). Each period sets `--role-sky-1…5` (flat bands from the top down to the horizon), the sky's ink and soft ink (≥4.5:1 on every band), the hand that draws the astro and the astro itself (the sun; the moon and stars at night). The dark theme's sky is always the night. `js/sky.js` keeps `data-scheme` and `data-sky` right (every minute, visibility, the system's change, another tab's `storage` event), sets the button's `aria-pressed`, and copies `--role-sky-1` into both `theme-color` metas (one per system scheme, static values `--color-day-1` and `--color-night-1`).
- The header draws the sky as a hard-stop gradient counted from the horizon (`--h5` … `--h2`) and places the one astro drawing (`.astro`, a disc and the urucum loop) by `--sun-*` in the day and `--moon-*` at night: the sun big, rising behind the band and running off the edge; the moon small and high, about a fifth of the sun. Each page and width sets those variables (`.site-head--home` for the home). The sun rises a little when the home opens (the one moving thing; not under reduced motion).
- Urucum is the one marking colour: the next activity's loop, today's stroke, the primary buttons, the open page's link and the nav pill. Pages take landscape colours (Agenda urucum, Comércio ipê-rosa) on their doors. Groups (sectors): `js/colors.js` maps a sector to `var(--role-series-N)` (fixed for the eight sectors in `SECTOR_SERIES` — the groups of the organizations survey, which use all eight series — then the series of a listed sector absent from the sheet, then a hash) and sets it as `--sector` on the node; they show as dots (`.dot`), never as shapes. `sectorsOf`/`sectorRank` (the chips' order, also the order colours are given in) live there too. Comércio's categories carry no colour.
- Fonts: Bricolage Grotesque (the voice: greeting, dates, page titles, day heads; one variable woff2 with the optical-size axis, weights 500–800) and Inter (reading and controls; variable, 400–700), self-hosted in `fonts/` with their OFL texts, declared and preloaded. The flyers set the same two (Bricolage with its optical size pinned at 96, see Flyers); Barlow is gone, but `fonts/OFL-barlow.txt` stays: the mark's N and S are traced from Barlow Condensed 800. No request goes to Google Fonts.
- Text sizes in `style.css` are in rem, and so are the boxes that hold text, so a larger default font size grows them together; `flyers.css` stays in px (fixed 1080×1350 canvas). Media queries are in px except the two narrow ones, which are in em (see below).
- Layout widths: phone first; 600px wider gutters and a centred bottom sheet; 760px the links on the sky (no bar at the foot), the page's name under them, the home's actions and "Também na agenda", Comércio's business rows; 1100px two columns on the agenda (panel 380px; Comércio's information card takes the panel's place) and the home's calm desk (the next activity at left, the doors stacked at right); 1280px panel 420px and the month with titles written in; under 22.4375em (359px at the default 16px: small phones, 200% zoom, or a large default font size) the header, the doors and the contacts reflow, and under 16.1875em (259px) the panel's buttons shrink. Phones on their side: see "PWA and offline".

## PWA and offline

- `sw.js` is network-first for every same-origin GET and for the CSVs (which may be on another origin): the live site and sheets always win and the cache is only the fallback, so there is no version to bump on deploy. `SHELL` is precached on install, because the first visit isn't controlled yet and only SHELL gets saved then: keep it in step with the three pages and every file they load (stylesheets, fonts, the band `assets/faixa.svg`, the module graphs from `js/home.js`, `js/app.js` and `js/comercio.js`, the vendored script, the manifest icons, the favicons); the screenshots and `og-image.png` stay out. Copies are keyed by absolute URL, pages without their query (so `?tema=` or `?utm_…` links don't multiply). Saved CSV copies get an `X-Cached-At` stamp (exposed to the page for a cross-origin CSV), which makes `fetchAgenda` show the "Sem conexão" notice. The cache is `nos-dourados-v1`; activation deletes only older `nos-dourados-*` caches, so other apps on the same origin (GitHub Pages) keep theirs. `CSV_URL` and `COMMERCE_CSV_URL` reach the worker as two `csv` parameters (`sw.js?csv=…&csv=…`, `registerWorker` in `js/page.js`, the same address from every page or each would replace the others' worker), so changing either registers a new worker.
- `index.html` and its folder share one saved copy; offline, only addresses of the app's own folder fall back to the saved home page (deeper ones would load it at the wrong base, unstyled). Activation also prunes the cache to SHELL plus the two CSVs, so removed files and an old spreadsheet's copy don't linger.
- Two defensive paths, both harmless where they aren't needed: a response that followed a redirect (the published Google Sheets CSV answers 307 to googleusercontent.com) goes back to the page as a plain copy, because Playwright's Firefox build never delivers a redirected response from `respondWith` (the page's fetch hangs; stock Firefox 156 is fine); and `fetchSheet` in `js/page.js` falls back to the saved copy (`caches.match`) when the fetch throws, because Firefox's offline mode as emulated in tests doesn't ask the worker for `no-store` requests.
- `manifest.webmanifest`: id `/nos-dourados` (never change it: a new id is a new app; `./` would resolve to the origin root on a sub-path host such as GitHub Pages), name and short_name "NOS Dourados", `start_url` `./` (the home), `shortcuts` to Agenda and Comércio, `theme_color` #6FAEE3 (the day sky's top band, the static light `theme-color`; neither can read CSS variables), `background_color` #F2E3D7 (the clay), no orientation lock (WCAG 1.3.4), four narrow screenshots (three of the agenda, one of Comércio) and one wide one.
- The head has PNG favicons (16/32/48), the apple-touch-icon, `apple-mobile-web-app-*` (status bar "black": "black-translucent" would put the white clock over the light skies, and needs a test on a real iPhone) and the og/twitter tags. `og:url`, `og:image` and `canonical` use the absolute https address, because crawlers don't resolve relative URLs; `og:image` carries `?v=4` (bump it when the image changes).
- Assets are rendered from HTML by `node assets/render.cjs [icons|og|shots]`, which serves the folder itself and stamps each PNG with its origin (a `tEXt` chunk under the impeccable skill's keyword: `impeccable embed-prompt <file> --read` shows it, `--scan assets` lists files without one) (Playwright: `PLAYWRIGHT_CORE`/`CHROMIUM` env vars, a local `playwright-core` install, or the maintainer's paths; a refused capture is tried once more). `assets/icon.html` (variants `#any`, `#maskable`, `#apple`, `#favicon`, drawn at the viewport size) prints the NOS mark (`MARK` in `js/icons.js`) on the dawn sky over the band and the clay, its O the sun inside the urucum loop; the favicons are that sun in its loop alone on the sky, the loop drawn as a stroke from its centre line kept in `icon.html`. `assets/og-image.html` (the link preview) is the home's first view at poster scale: the dawn sky, the mark, "Dourados" and the full name of `js/config.js` at the left, the big sun rising behind the band at the right; its type is sized for the ~330px-wide WhatsApp bubble. Both set their own `data-scheme="light"` and `data-sky="dawn"`, use the theme roles and set `html[data-ready]` when done. The screenshots are the site itself (`agenda.html`, `comercio.html`) in the light theme on a fixed day (2026-10-15, 10h, the day sky).
- Landscape is allowed. With `viewport-fit=cover`, the header, `.shell`, the home, the footer, the bar at the foot, the full-width phone sheet and the skip link pad with `env(safe-area-inset-*)`; on phones on their side (`max-height: 500px` and landscape) the sheet takes nearly the whole height, and in flyer mode the preview stands beside the format bar and the style picker.

## Designs

`design/` holds the designs as plain HTML, one artboard per file, and `design/index.html`, a canvas that shows them all side by side like a Figma page. Design work for this project happens there, in HTML: not in Pencil (pen.dev) or OpenPencil, even when a session offers their MCP tools or skills (they are set up for the user, not for this project). The impeccable skill's raster comps (`.impeccable/mocks/`, git-ignored) are its working files; what is kept for reference and approval is `design/`. With the project served (`python3 -m http.server 8000`), open http://localhost:8000/design/: drag or scroll to move, Ctrl/⌘ + scroll or pinch to zoom, double-click a design to fit it, `?` for the shortcuts, `#<file name>` (e.g. `#marca-nos`) opens on one design. From localhost the explorer polls the files (HEAD requests every second) and reloads what changed: a design file reloads its frame, a shared file (`../css/theme.css`, `assets/design.css`, `assets/icons.svg`) reloads them all, `designs.json` rebuilds the canvas. The folder is deployed with the site (harmless: `noindex`, not linked, not in `sw.js`'s SHELL).

- The canvas: **Céu · Terra** (approved 2026-10-27 and built: the reference for the site; `direcao-ceu-terra-*.html` with `assets/direcao-ceu-terra.css`, light and dark via `?tema=escuro`, the light artboards drawn at 5:50, the amanhecer sky), **Céu · Pipas** (kept for later), **Céu · a base** (D3 · Céu) and **A faixa · pesquisa** (`faixa-pesquisa.html`: why the band exists and how to make the real one with the Reserva's artists), the **Marca** (`marca-nos.html`, the mark in the new world with the shipped icons and link preview) and the **Panfletos** (the four flyers under the day, dawn, dusk and night skies: each `panfleto-*.html` draws its flyer with `js/flyer.js` from real agenda rows kept in `assets/panfletos.js`, so it is always what the site exports; `?atividade=<key>` picks the activity and with it the sky of its hour). The Folhinha's screens, components and first directions were removed by the redesign (in git history before it: `git show e79135c:design/<file>`). The direction artboards load their fonts from Google Fonts (they are the round's records); the site doesn't.
- A design file: `../css/theme.css` and `assets/design.css` in the head (and a direction's own stylesheet where it has one), then a `<style>` with its own rules; the body's first element is the artboard, with its real size (phones 390 × 844, desktop 1440 × 900, flyers 1080 × 1350; boards grow with their content). The explorer measures that element to size the frame. Content in pt-BR, class names in English.
- Colours, fonts and radii only through `css/theme.css` (the palette `--color-*`, `--font-ui`, `--font-display`, `--radius*`), so a palette change reaches the designs too — except a record of a past decision, which may freeze its colours in its own style and say so.
- Icons: `<svg class="…"><use href="assets/icons.svg#map-pin"/></svg>`, sized by the class's width/height and coloured by `color`. The sprite holds the Lucide icons in use (the drawings of `js/icons.js` where the site has them) and the NOS mark (`#marca-nos`, the paths of `MARK`; its loop takes `--mark-loop`); add a `<symbol>` for a new one. XML comments in the sprite can't contain `--`.
- `designs.json` lists the canvas: sections (rows, top to bottom) and their designs (left to right), each `{ "file", "title", "width", "height" }` with the artboard's size (the explorer corrects it from the rendered page, but a right size keeps the canvas from jumping while loading). A new design = a new HTML file (start from a copy of a similar one) + its line here. Put a proposal in its own file next to the design it would replace, so the current one stays as the reference until the change is approved and built.

## Git workflow

One developer and little parallel work, so keep git light:

- No pull requests. Work lands on `main` directly.
- Worktrees (`.claude/worktrees/`, git-ignored) are fine for isolating a task, but when it is done, fast-forward `main` to the worktree branch (`git merge --ff-only <branch>` in the main checkout; rebase the branch on `main` first if `main` moved), push `main`, then delete the branch (local and remote) and remove the worktree. Nothing stays parked on a side branch.
- Commit once per significant chunk of work (one feature, fix or doc change per commit) rather than one big commit, so each commit is easy to review on its own.
- Pushing `main` publishes the site (GitHub Pages builds from `main` / root), so check the change works before pushing.
