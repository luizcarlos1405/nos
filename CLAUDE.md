# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"NOS Dourados" (NOS = Núcleo de Organização Social, provisional name) is a static, no-build site (plain HTML/CSS/vanilla ES modules, no package.json, no tests, no linter) of three pages:

- **Início** (`index.html`, `js/home.js`): one sentence and two doors, today's calendar sheet with the next activities and the phone book's first sheet with a few businesses drawn at random.
- **Calendário** (`calendario.html`, `js/app.js`): one permanent calendar of the activities of the social movements, unions, student groups, Indigenous and quilombola organizations, councils and parties of Dourados/MS. For each activity it generates a WhatsApp-ready message and a 1080×1350 PNG flyer. It was copied from the "Calendário de Luta" project (election campaign agenda) and redesigned: only the colour palette was kept. Until 2026-10-26 it was `index.html`.
- **Comércio** (`comercio.html`, `js/comercio.js`): the businesses that answered the network's registration form (a Google Form), as an A–Z phone book: one sheet per letter, each business with what it offers, its WhatsApp numbers (with a phone glyph to call), Instagram and links, search, category chips and an "Indicar no WhatsApp" message.

Language rule: development (code, identifiers, CSS classes, comments, commit messages) in English; all content and UI strings in Brazilian Portuguese (pt-BR). Content-like slugs (flyer PNG filenames: `folha`, `mes`, `cartaz`, `cancelada`) stay in pt-BR.

Product truth lives in `PRODUCT.md`; the visual direction ("Folhinha", the tear-off wall calendar) and the direction contracts live in `.impeccable/surfaces/` (`calendario-html.md`, `comercio-html.md` for the phone book, `index-html.md` for the home); `DESIGN.md` (+ `.impeccable/design.json`) documents the built design system. The design source is `design/`: one HTML file per artboard (brand mark, components, phone and desktop screens, the four flyers, the first visual directions), all shown on one zoomable canvas by `design/index.html` (see "Designs"). Use the project's impeccable skill for UI work.

## Running

The pages must be served over HTTP: ES modules and the `fetch` of the CSVs fail under `file://` (an inline script in `calendario.html` and `comercio.html` shows an error notice in that case).

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

Deploy = publish the whole folder to any static host. It is live on GitHub Pages at https://nos.dourados.social (`CNAME`); `SITE_URL` in `js/config.js` and the link-preview `canonical`/`og:url`/`og:image` tags of the three pages hold that address.

## Pages and navigation

- Three HTML files linked with plain `<a href="calendario.html">` links, so any static host serves them (no router, no rewrites; GitHub Pages also answers `/calendario` without the extension, but links and messages always use the file name). `index.html` is the root.
- The header card of Calendário and Comércio ends in folder tabs (`nav.site-tabs`, one `a.site-tab` per page, the open one with `aria-current="page"`, cut into the wall: it takes `--role-wall` and runs into the page). The brand links to `./` and says "(página inicial)" to screen readers; Início has no tabs (its doors are the navigation) and its brand carries `aria-current="page"`. `.masthead.has-tabs` tightens the brand's bottom padding.
- `index.html`'s head holds the notes on the shared tags (browser colour, theme, icons, manifest, home-screen app, link preview); `calendario.html` and `comercio.html` repeat the tags with a pointer there, changing only the title, descriptions and addresses. `theme-color` and `data-theme` must stay equal in the three.
- `js/page.js` is what the pages share: `$`, `el`, `escapeHtml`, `safeUrl`, `initPage(name)` (the brand from `js/config.js`, the tab title "Comércio · NOS Dourados", the icons of `[data-icon]` nodes), `showNotice`/`showOffline(savedAt, what)`/`announce` (`#notice`, `#live`), `readSheet(url)` (fetch with the cache fallback, `decodeCSV`, `parseCSV`, plus `savedAt` from the worker's `X-Cached-At`), and `registerWorker()`.

## Data

The agenda is a Brazilian CSV (`;`, UTF-8 BOM, dd/mm/aaaa) read from `CSV_URL` in `js/config.js` (now `data/agenda.csv`; later a published Google Sheets CSV). Columns (pt-BR headers, matched loosely by `COLUMN_ALIASES` in `js/events.js`: accents/case/spaces normalized, English aliases accepted): `Título`, `Dia` (required; a full date with the year — yearless dates are rejected so they can't change meaning at New Year); `Dia final` (multi-day; a yearless value takes the start's year, or the next one if it would fall before the start), `Horário`, `Término` (both accept `9h`, `9h30`, `09:30` and spreadsheet time cells like `14:00:00`/`2:00 PM`; an end time alone renders "até 12h"), `Tipo`, `Organização` (split on `,`/`;` outside parentheses, main first → `event.orgs`), `Setor` (alias `Categoria`), `Local`, `Cidade` (empty, `HOME_CITY` or `HOME_CITY` + state = here → `event.city` is `''`), `Descrição`, `Contato`, `Link` (action link), `Fonte` (source post), `Visível` (unchecked = draft, skipped silently, `isHidden`), `Cancelado` + `Motivo Cancelamento` (`isChecked`), and `Notas internas` (ignored by the site). `parseCSV` (`js/csv.js`; the Windows-1252 fallback is in `decodeCSV`) returns each record's spreadsheet row (`lines`) so notices name the right "Linha N" even after blank rows. `buildEvents` returns `{ events, invalid, warnings, missing }`: rows without a title or a full date are reported (folded list in the notice), an unreadable `Dia final` keeps the row as one-day with a warning, and missing `Título`/`Dia` headers produce one error naming them. `data/agenda.csv` was extracted (and adversarially verified) from an Instagram survey of the organizations (`../coleta-instagram/*.md`, next to the project folder and kept outside this repository) and the raw captions; its `Notas internas` say what is uncertain and why rows are hidden.

Comércio reads `COMMERCE_CSV_URL` (now `data/comercio.csv`; later the form's answer sheet published as CSV), same formats. The columns are the Google Form's questions as they are, matched by a word they contain (`COLUMNS` in `js/businesses.js`, checked in order: consent before contact before other networks, so "Como podemos entrar em contato?" and "Podemos incluir … com a rede?" land right): `Carimbo de data/hora` (ignored), `Nome da empresa ou negócio` (required), `Cidade e estado`, `Qual o Instagram da empresa?`, `O que sua empresa oferece?`, `Como podemos entrar em contato?`, `Sua empresa tem site ou outra rede social?`, `Podemos incluir sua empresa na nossa planilha e compartilhar suas informações com a rede?` (only a yes is shown, `isChecked`; a sheet without the column shows every row), plus columns the NOS team adds to the right: `Categoria` (free text; the order of the chips is `COMMERCE_CATEGORIES`, then alphabetical), `Visível` (`isHidden`) and `Notas internas` (ignored). `buildBusinesses` returns `{ businesses, invalid, missing }` sorted by name (pt-BR collation); rows without a name are reported, rows without consent or hidden are skipped silently. What it reads out of the free text, and nothing else: the name and a subtitle (" - " or a trailing "(…)"), the sheet's letter (`#` for digits and signs), an all-caps offer in sentence case, the city (`HOME_CITY` with or without the state → `''`; others title-cased, another state as "City/UF"), Brazilian phone numbers with their area code in the contact answer (11 digits with a 9 → mobile: WhatsApp link and a call glyph; 10 → landline; numbers without the area code stay text), the Instagram handle (a link, "@handle" or a bare handle, accents stripped, a bare "Sim"/"Instagram" refused), the links of the other-networks answer named by domain (Google, Facebook, TikTok, Instagram, WhatsApp, else "Site"), and the answers' own words as notes when they add something (`contactNote` when no number was found, `otherNote` unless it only names channels already shown or says no). Ids are `biz-<slug of the name>`; `search` is the accent-free text every typed word must appear in. `data/comercio.csv` holds the 17 answers of 2026-10-26 verbatim, with a `Categoria` filled by hand.

## Architecture

Calendar data flow: `app.js` fetches CSV → `csv.js` `parseCSV` → `events.js` `buildEvents` → views (`agenda.js`, `month.js`) → clicking an activity fills the panel ("bench") from `app.js`, with `whatsapp.js` (message + `wa.me` link + preview) and `flyer.js` (flyer DOM + PNG export). Comércio: `comercio.js` → `page.js` `readSheet` → `businesses.js` `buildBusinesses` → letter sheets; Início: `home.js` reads both sheets.

- `js/comercio.js` keeps one `state` (`query`, `categories` as `matchKey` values). The chips are built once and only flip `aria-pressed`, so focus stays on them; `render()` rebuilds the count line and the list (letter sheets as `section.sheet.letter-sheet` with an `h2` letter, businesses as `article.biz` with an `h3` name and a `dl.biz-contacts`), or a blank sheet naming the search and the categories, with "Buscar em todas as categorias" when dropping the categories finds something and "Ver todos os negócios". The search filters as you type and announces the count after a pause; Enter closes the keyboard. `breakable()` lets offers and notes wrap after their slashes. "Indicar" is a `wa.me/?text=` link with `buildBusinessMessage` (`whatsapp.js`, closing with `COMMERCE_CLOSING_LINE`): a glyph on phones (`aria-label`), written out under the offer from 760px.
- `js/home.js`: today's sheet head (two-digit day, red on Sundays and holidays, "Hoje"), the next three activities (`upcomingEvents` in `events.js`, the first with the yellow "Próxima"; CSS shows only the first under 760px), the count and four businesses drawn at random (three under 760px), each with dot leaders to its category. A sheet that can't be read leaves its door with its static text and button. Each door's button link stretches over its sheet (`.door-go::after`).

- `js/app.js` is the only stateful module: one `state` object (view, sector filter set and organization filter as `matchKey` values, selected activity, past toggle, month/year, selected day, the month grid's keyboard position) and all DOM wiring. Other modules are render/format helpers that take data and return DOM nodes or strings. Rendering is full re-render via `replaceChildren()`; no framework.
- Focus across re-renders: every rebuildable focusable node carries `data-focus` (`chip:<key>`, `line:<id>`, `day:<key>`, `month:prev|next|today|title`, `past-toggle`, `clear-filters`); `rerender()` puts focus back on the new twin (with fallbacks in `FOCUS_FALLBACK`). Screen-reader announcements go through the persistent `#live` region (`announce()`), never through re-rendered nodes.
- "Now" is not frozen: `today`/`todayKey` are updated by `tick()` (every minute, on `visibilitychange`/`pageshow`); the view re-renders when the day turns or the next activity changes, and the CSV is fetched again after 30+ minutes hidden (`reload()`, keeping filters and selection while they still exist; if the fetch fails, what is on screen stays, without an error).
- Event object shape is defined in `buildEvents`. Ids are stable across re-fetches: `ev-<dateKey>-<slug of the title>` (`-2`, `-3`… for repeats), so rows inserted above don't swap the open activity for another. Dates are local `Date` objects, never UTC; `dateKey` (`YYYY-MM-DD`) is compared as a string. Multi-day activities have `endDate`/`endDateKey`; helpers `lastDayKey`, `dayKeys`. Times are minutes since midnight (`time`, `endTime`) next to the raw strings; formatters fall back to the raw text. `matchKey` (punctuation-free) matches people-typed names (sectors, organizations, cities).
- Agenda (`agenda.js`): a pad of day sheets (`renderSheet`), today's always on top; day numbers on sheets are two-digit (`sheetNumber`). Past days are hidden until "Ver N atividades anteriores"; a multi-day activity that started before today is printed on today's sheet ("Em andamento, até …", `groupByShownDay`); each day lists its own activities by time, then the running ones (`dayOrder`). With filters on and nothing ahead, a blank sheet with "Ver atividades anteriores" / "Limpar filtros".
- Month (`month.js`): Sunday-first page, built as week rows; one-day activities are marks inside the day, multi-day ones are bars in lanes over the week (`weekBars`, each day reserving only the lanes that cross it). The grid is one tab stop with arrow/Home/End/PageUp/PageDown navigation (`onMove`). The selected day's sheet is printed under the page (only while that day is on the page's month); from 1280px a holiday's name sits on its own line under the numeral and its week (`has-holiday`) makes room for two lines, so the bars stay level; turning the month picks today or the month's first day with activities; picking a grey day flips to its month.
- Red-letter days: Sundays and national holidays (`holidays.js`: fixed dates + Good Friday from Easter; `EXTRA_HOLIDAYS` in config for local ones — none confirmed yet).
- The next activity (`findNext` in `app.js`, computed on the filtered list, through `findNextEvent`/`upcomingEvents` in `events.js`, which the home shares): first non-cancelled activity starting today-or-later (today's count until an hour after they start; periods already running are not "next"). It gets the yellow "Próxima" badge on its start day's sheet and the yellow time plate — yellow is reserved for that (the month grid doesn't mark it).
- Panel ("bench"): bottom sheet under 1100px, persistent sticky column at ≥ 1100px (`desktop` in `app.js` and the 1100px media queries in `style.css` must agree). The phone sheet is a modal dialog (`setModal`: `role=dialog`, `aria-modal`, `inert` behind it), adds a history entry so the phone's Back button closes it (`openSheet`/`closeSheet`/`hideSheet` + `popstate`), and can be dragged down by its head (`wireSheetDrag`, `--drag`). Facts list (organization with full names from `ORG_NAMES`, period, place, type, contact, link, source), description, Mensagem/Panfleto tabs (`showPanel`; flyer mode folds facts and description via `data-panel`, keeping only the organization row on desktop; on screens under 700px tall, switching to Panfleto scrolls the format bar to the top), sticky action bar. Phone numbers in `Contato` become links (`contactNode`: mobiles → `wa.me`, landlines → `tel:`); `Link`/`Fonte` go through `safeUrl` (only http(s); bare domains get `https://`; anything else is shown as text).
- Flyers (`flyer.js` + `css/flyers.css`): `FLYER_STYLES` (`day` "Folha do dia", `month` "Calendário do mês", `poster` "Cartaz") and `NOTICE_STYLE` (`notice` "Aviso de cancelamento", forced for cancelled activities). Class prefixes `dy-`, `mo-`, `po-`, `nt-` under `.fl--<id>`. `renderFlyer` builds a fixed 1080×1350 node (`aria-hidden`); the panel preview scales it with `transform: scale()` on `#flyer-scaler`. Sizes and line breaks are planned deterministically from embedded Barlow glyph widths (no DOM measurement), so preview and PNG match. Export uses the global `htmlToImage` (vendored in `js/vendor/`) after `document.fonts.ready`. `.impeccable/flyer-lab.html` renders every style for real and stress-test activities with an automatic layout audit (dev only; English).
- Colours: every colour is a custom property in `css/theme.css`, in two layers — palette (`--color-*`) and roles (`--role-*`). `style.css` and `flyers.css` use roles only; the only literals are `transparent`, `currentColor` and, inside `@media (forced-colors: active)`, system colours. Sector colours: `js/colors.js` maps a sector to `var(--role-series-N)` (fixed for the eight sectors in `SECTOR_SERIES` — the groups of the organizations survey, which use all eight series — then the series of a listed sector absent from the sheet, then a hash) and sets it as `--sector` on the node; `sectorsOf`/`sectorRank` (the chips' order, also the order colours are given in) live there too, so the home paints the same colours. Comércio's categories carry no colour. Themes: `[data-theme='name']` blocks in `theme.css`, chosen by `data-theme` on `<html>` in the three pages or, for trying one out, `?tema=<name>` in the address. The `theme-color` meta and the manifest colours can't read variables.
- Fonts: Barlow and Barlow Condensed, self-hosted in `fonts/`, declared in `theme.css`.
- Text sizes in `style.css` are in rem, and so are the boxes that hold text (numeral and time columns, month bars and lanes), so a larger default font size grows them together; `flyers.css` stays in px (fixed 1080×1350 canvas). Media queries are in px except the two narrow ones, which are in em (see below).
- Layout widths: phone first; 600px wider gutters and a centred bottom sheet; 760px Comércio's rows (contacts in their own column, "Indicar" written out) and the home's doors side by side; 1100px two columns (panel 380px; Comércio's information sheet takes the panel's place) and 48px page tabs; 1280px panel 420px and the month page with titles written in; under 22.4375em (359px at the default 16px: small phones, 200% zoom, or a large default font size in the browser) the sheet heads and lines reflow, and under 16.1875em (259px) the panel's date stacks. Phones on their side: see "PWA and offline".

## PWA and offline

- `sw.js` is network-first for every same-origin GET and for the CSVs (which may be on another origin): the live site and sheets always win and the cache is only the fallback, so there is no version to bump on deploy. `SHELL` is precached on install, because the first visit isn't controlled yet and only SHELL gets saved then: keep it in step with the three pages and every file they load (stylesheets, fonts, the module graphs from `js/home.js`, `js/app.js` and `js/comercio.js`, the vendored script, the manifest icons, the favicons); the screenshots and `og-image.png` stay out. Copies are keyed by absolute URL, pages without their query (so `?tema=` or `?utm_…` links don't multiply). Saved CSV copies get an `X-Cached-At` stamp (exposed to the page for a cross-origin CSV), which makes `fetchAgenda` show the "Sem conexão" notice. The cache is `nos-dourados-v1`; activation deletes only older `nos-dourados-*` caches, so other apps on the same origin (GitHub Pages) keep theirs. `CSV_URL` and `COMMERCE_CSV_URL` reach the worker as two `csv` parameters (`sw.js?csv=…&csv=…`, `registerWorker` in `js/page.js`, the same address from every page or each would replace the others' worker), so changing either registers a new worker.
- `index.html` and its folder share one saved copy; offline, only addresses of the app's own folder fall back to the saved home page (deeper ones would load it at the wrong base, unstyled). Activation also prunes the cache to SHELL plus the two CSVs, so removed files and an old spreadsheet's copy don't linger.
- Two defensive paths, both harmless where they aren't needed: a response that followed a redirect (the published Google Sheets CSV answers 307 to googleusercontent.com) goes back to the page as a plain copy, because Playwright's Firefox build never delivers a redirected response from `respondWith` (the page's fetch hangs; stock Firefox 156 is fine); and `fetchCSV` in `js/app.js` falls back to `caches.match(CSV_URL)` when the fetch throws, because Firefox's offline mode as emulated in tests doesn't ask the worker for `no-store` requests.
- `manifest.webmanifest`: id `/nos-dourados` (never change it: a new id is a new app; `./` would resolve to the origin root on a sub-path host such as GitHub Pages), name and short_name "NOS Dourados", `start_url` `./` (the home), `shortcuts` to Calendário and Comércio, `theme_color` #E4002B (keep it equal to the `theme-color` meta; neither can read CSS variables), `background_color` #EFEFEC, no orientation lock (WCAG 1.3.4), four narrow screenshots (three of the calendar, one of Comércio) and one wide one.
- The head has PNG favicons (16/32/48), the apple-touch-icon, `apple-mobile-web-app-*` (status bar "black": "black-translucent" would need a fixed red strip under the status bar and a test on a real iPhone) and the og/twitter tags. `og:url`, `og:image` and `canonical` use the absolute https address, because crawlers don't resolve relative URLs.
- Assets are rendered from HTML by `node assets/render.cjs [icons|og|shots]`, which serves the folder itself, passes `index.html`'s `data-theme` to the templates as `?tema=` and stamps each PNG with its origin (a `tEXt` chunk under the impeccable skill's keyword: `impeccable embed-prompt <file> --read` shows it, `--scan assets` lists files without one) (Playwright: `PLAYWRIGHT_CORE`/`CHROMIUM` env vars, a local `playwright-core` install, or the maintainer's paths). `assets/icon.html` (variants `#any`, `#maskable`, `#apple`, `#favicon`, drawn at the viewport size) prints the NOS mark (`MARK` in `js/icons.js`) on a day sheet, paper under the red binding strip; the favicons are its red O alone, drawn as a stroke from the loop's centre line kept in `icon.html`. `assets/og-image.html` (the link preview) lays the folhinha's sheet across the red card's whole width, as WhatsApp shows the image whole above the title, and prints the mark where a day sheet prints its day, with the city and the full name of `js/config.js` beside it; its type is sized for the ~330px-wide bubble. Both use the theme roles and set `html[data-ready]` when done. The screenshots are the site itself (`calendario.html`, `comercio.html`) on a fixed day (2026-10-15).
- Landscape is allowed. With `viewport-fit=cover`, `.masthead`, `.shell`, the full-width phone sheet and the skip link pad with `env(safe-area-inset-*)`; on phones on their side (`max-height: 500px` and landscape) the sheet takes nearly the whole height, and in flyer mode the preview stands beside the format bar and the style picker.

## Designs

`design/` holds the designs as plain HTML, one artboard per file, and `design/index.html`, a canvas that shows them all side by side like a Figma page. Design work for this project happens there, in HTML: not in Pencil (pen.dev) or OpenPencil, even when a session offers their MCP tools or skills (they are set up for the user, not for this project). The impeccable skill's raster comps (`.impeccable/mocks/`, git-ignored) are its working files; what is kept for reference and approval is `design/`. With the project served (`python3 -m http.server 8000`), open http://localhost:8000/design/: drag or scroll to move, Ctrl/⌘ + scroll or pinch to zoom, double-click a design to fit it, `?` for the shortcuts, `#<file name>` (e.g. `#celular-mes`) opens on one design. From localhost the explorer polls the files (HEAD requests every second) and reloads what changed: a design file reloads its frame, a shared file (`../css/theme.css`, `assets/*`) reloads them all, `designs.json` rebuilds the canvas. The folder is deployed with the site (harmless: `noindex`, not linked, not in `sw.js`'s SHELL).

- A design file: `../css/theme.css`, `assets/design.css` and `assets/components.css` in the head, then a `<style>` with its own rules; the body's first element is the artboard, with its real size (phones 390 × 844, desktop 1440 × 900, flyers 1080 × 1350; boards like `componentes.html` grow with their content). The explorer measures that element to size the frame. Content in pt-BR, class names in English.
- Colours, fonts and radii only through `css/theme.css` (the palette `--color-*`, `--font-ui`, `--font-display`, `--radius*`), so a palette change reaches the designs too. Weights: Barlow 500/600/700, Barlow Condensed 600/700/800 (the site has no 400 face).
- `assets/components.css` is the component library (`.chip`, `.org-select`, `.badge`, `.stamp-cancelada`, `.city-tag`, `.button-primary`, `.button-secondary`, `.icon-button`, `.day-sheet`, `.activity-line`, `.nos-mark`, and since 2026-10-26 `.sheet-top` (binding and perforation as the site draws them), `.site-tabs`/`.site-tab`, `.search-pill`, `.letter-sheet`, `.biz` and `.contact-row`; elements as `.day-sheet__head`). Designs use these classes and put per-use differences inline. A change there reaches every design that uses the component: check them on the canvas. `componentes.html` and `marca-nos.html` show the components on their own.
- Icons: `<svg class="…"><use href="assets/icons.svg#map-pin"/></svg>`, sized by the class's width/height and coloured by `color`. The sprite holds the Lucide icons in use (the drawings of `js/icons.js` where the site has them) and the NOS mark (`#marca-nos`, the paths of `MARK`; its loop takes `--mark-loop`, so `.nos-mark` on paper sets `color` to ink and `--mark-loop` to red); add a `<symbol>` for a new one. XML comments in the sprite can't contain `--`.
- `designs.json` lists the canvas: sections (rows, top to bottom) and their designs (left to right), each `{ "file", "title", "width", "height" }` with the artboard's size (the explorer corrects it from the rendered page, but a right size keeps the canvas from jumping while loading). A new design = a new HTML file (start from a copy of a similar one) + its line here. Put a proposal in its own file next to the design it would replace, so the current one stays as the reference until the change is approved and built.
- The files were converted on 2026-10-26 from `design.pen`, the Pencil file the project used before (still in git history: `git show d58c566:design.pen`). That is why they keep Pencil's layout model (flex everywhere, `flex-shrink: 0` items, `align-self: stretch` for full-width children) and its layer notes as HTML comments (ARIA roles, sticky behaviour, sizes). Text that Pencil set in Barlow 400 is 500 here, as on the site.

## MCP servers

- `.mcp.json` (project scope) declares the Namecheap MCP (`https://mcp.namecheap.com/mcp`, HTTP, OAuth sign-in to the Namecheap account; run `/mcp` in Claude Code to connect). ## Git workflow

One developer and little parallel work, so keep git light:

- No pull requests. Work lands on `main` directly.
- Worktrees (`.claude/worktrees/`, git-ignored) are fine for isolating a task, but when it is done, fast-forward `main` to the worktree branch (`git merge --ff-only <branch>` in the main checkout; rebase the branch on `main` first if `main` moved), push `main`, then delete the branch (local and remote) and remove the worktree. Nothing stays parked on a side branch.
- Commit once per significant chunk of work (one feature, fix or doc change per commit) rather than one big commit, so each commit is easy to review on its own.
- Pushing `main` publishes the site (GitHub Pages builds from `main` / root), so check the change works before pushing.
